# Space Patriot Unreal port audit

Updated 2026-09-27 against the original browser source, Unity restoration, this Unreal project, and fresh Unreal 5.8 Editor checks. The original has 91 JavaScript/GLSL modules and thirteen extracted engine runtimes. A source catalog, test, or Blueprint parent does not by itself make that behavior playable. [FULL_WORLD_PORT_INVENTORY.md](FULL_WORLD_PORT_INVENTORY.md) maps original modules to concrete Unreal gaps and full-world acceptance checks. [UNREAL_FULL_PORT_AND_ASSET_PLAN.md](UNREAL_FULL_PORT_AND_ASSET_PLAN.md) sets the integrated implementation sequence and free-asset shortlist.

## Current integrated slice

`L_KellenReachWalk` holds a Shooter-template on-foot character, rifle pickup, port/cargo dressing, freight terminal, parked flyable ship, source-seeded `ASPWorldSurface`, and `BP_WorldRuntime` together. `ASPPlayLoopDirector` handles board/exit, launch/landing state, 19-world destination selection and hyperjump, switching visible Earth port actors and off-world dressing, and keeping society's active world aligned. The director route, keyboard N/J, and cockpit NAV buttons now share the ship's navigation state; jump progress and fuel are applied once. R or the MFD's AUTO ROUTE button can launch, climb, jump, approach, and try to land on a solid destination. `K/O` save and restore the physical journey; existing society/campaign/survey saves remain separate. A locally installed CC BY cruiser visually replaces the eight simple display parts and the flyable exterior; CC0 foliage and rocks are local dependencies. The old ship remains only as a fallback if that local exterior is not installed.

A fresh map load passed **102/102** saved-map checks across walk setup, navigation, population, play loop, respawn, and ship display (`Data/CohesiveWorldValidation.json`). The Editor target builds. Native automation passed **33/33** tests, including Earth→Mars→Jupiter travel, a connected board→launch→Mars jump→physical landing→exit→market purchase→reboard sequence, auto-route touchdown and manual takeover, shared MFD/keyboard route state, field-sample campaign progression, the case journal, journey save/restore, rock placement, and biome foliage placement. A live **Play in Selected Viewport** pass boarded at Kellen Reach, selected Mars with N, started auto route with R, landed on Mars, exited, scanned, collected a sample, and reboarded. Earlier respawn failures were corrected with `RED`/`BLUE` PlayerStart tags and a safer starter location. The integrated HUD now hides the Shooter score and floating AI debug labels while keeping the rifle and patrol mechanics. This is a verified short loop, not a full source-equivalent game or long-session validation.

## Original engine coverage

Worldworks and Terrainworks provide the bounded radial globe and local terrain/climate data. Storyworks provides the tested campaign graph and a first terminal interaction. Architectureworks has a tested layout model. Inventoryworks and combat have native simulations that still lack full physical interaction. Society and freight have a functional simulation plus one terminal path. Grassworks, Oceanworks, Fireworks, Spellworks, Pathworks, Machineworks, Weatherworks, and Creatureworks are **not fully ported**; visual or catalog placeholders are not engine parity. The original hundred-ship fleet and Unity cockpit validation are references, not completed Unreal assets.

The eight Space Patriot Blueprint handoffs are mostly native parents or shells. `BP_KestrelFlyable` and `BP_WorldRuntime` have authored K2 links with structural/runtime checks, but this is not a full Blueprint conversion of every original system. A true full-game port requires each system to drive a visible, player-reachable action and share one persistent state model.

## Next acceptance gates

1. Extend the verified Selected Viewport Earth→Mars loop to manual flight, return travel, save/reload, freight, combat, and a longer session; check collisions, controls, and screen readability after each transition.
2. Replace the shooter and wildlife placeholders with licensed or custom art and route their damage, inventory and rewards through the original systems.
3. Build a larger authored settlement plus streamed surrounding biomes, working NPC routines and ship traffic, then prove the offscreen simulation has visible consequences.
4. Implement physical ship interiors/cargo, campaign choice UI, audio, weather/ocean/Grassworks/Spellworks effects, and profile the combined world.
5. Validate save/reload, travel, combat, mission progression and performance in a packaged Windows build before an installer.
