# Space Patriot — Unreal Engine 5.8

This is the installable-game **development project**, played inside Unreal Editor for now. `L_KellenReachWalk` puts walking, the port, a flyable ship, world travel, landing, and freight interaction in one map. It is an integrated prototype, not yet a continuous playable equivalent of the original Space Patriot. [PROTOTYPE_SCOPE.md](PROTOTYPE_SCOPE.md) is the current fast internal-playtest target; the full original-game parity inventory remains a later backlog.

## Set up a clone

1. Install Unreal Engine 5.8, Visual Studio 2022 C++ Build Tools with the Windows SDK, Git and Git LFS. Run `git lfs install`, clone this repository, then run `git lfs pull` in the clone.
2. **Close Unreal Editor** and run `./Tools/InstallAllDependencies.ps1` in PowerShell from the project root. It verifies and installs the required local UE template content, Poly Haven CC0 terrain/foliage, and Viktor Hahn's CC BY cruiser exterior. The manifests pin the download URLs and checksums. These third-party binaries stay on each collaborator's computer and are not pushed to Git. `-List` shows dependencies; `-VerifyOnly` checks them without installing. Allow several minutes for a first import.
3. Open `SpacePatriotUnreal.uproject`. If Unreal asks, allow it to build the C++ module. Open `/Game/SpacePatriot/Maps/L_KellenReachWalk` if it is not already loaded. Use **Play > Selected Viewport**; this project does not require a separate play window.

On foot, use WASD and mouse, collect the nearby rifle, **E** to board at the ship's port-side hatch, **B** to scan near the current survey site, and **Shift+B** to collect a sample after scanning. At a port terminal, **F** accepts or delivers freight or handles a matching campaign objective; **3** selects ore/organics/crystal, **4** buys one unit into dock staging, **5** loads one into the ship hold, **6** unloads one, and **7** sells one staged unit. The board shows prices, stock, hold use, and credits. **H** cycles available cases, **M** opens or advances dialogue, and **1/2** choose dialogue options. **U** advances the local day/night clock by three hours; **T** remains flight assist. **F5** starts *The Water Ledger*. **F6** saves the existing society/campaign/survey slots. **K** saves the physical journey and its simulation snapshot, including local time; **O** restores that checkpoint. The Shooter template's score HUD and character/gun are mechanics placeholders.

In the ship, **Space** launches, **W/S/A/D** and **Space/Ctrl** move, arrow keys pitch/yaw, **Q/E** roll, **G** toggles gear, **N** chooses a destination, and **J** starts hyperjump when powered, clear of the station, above 2 km, and gear-up. At a solid world, slow below 80 m/s, descend within 650 m, and press **L** over a broad, level surface; landing deploys gear automatically and reports failures on the MFD. **E** exits after landing. **V** changes camera; **F1–F4** change MFD pages and **Tab** enables its pointer. On the NAV page, the clickable **DEST** and **JUMP** buttons operate the same route as N/J and show jump interlocks. The cockpit model and physical controls still need substantial art and interaction work.

The local cruiser replaces the eight simple Kestrel display pieces in this map and the playable exterior at runtime. It is a visual placeholder with the original ship's flight systems, not the final custom Kestrel or a walkable multi-deck interior. The project keeps a fallback legacy flight map, `/Game/SpacePatriot/Maps/L_KestrelFlight`, for regression checks.

## What is connected

- The unified map contains the authored Kellen Reach apron, local textured cargo/rocks, a shooter character and AI patrols, native Worldworks terrain, society runtime, and Earth/remote freight terminals. Shooter respawns use the template's required `RED`/`BLUE` PlayerStart tags.
- A persistent flyable ship uses the native travel state machine to select among 19 source worlds. The physical surface activates on arrival; 13 solid world heightfields and 19 climate atlases are loaded from the source data. Non-Earth landing sites receive bounded biome-specific rocks, outpost supplies, and optional locally imported plants. Gas worlds do not allow landing.
- Society, campaign, field survey, freight, and travel state have native data/simulation components and independent save paths. On-foot scan/sample and the port board's market/hold actions now reach these components. `K/O` connects the ship, world, destination, and on-foot possession to a journey save. A single atomic save, rendered settlements, and the full source interaction loop are still missing.

The visual planet outside the local area is procedural, and a local dressing set is **not** a finished planet. Rendered cities, everyday civilian behavior, all original ships and interiors, full wildlife combat, broad quest presentation, sound, weather/ocean/Grassworks/Spellworks parity, and multiplayer still need implementation. See [PORT_AUDIT.md](PORT_AUDIT.md) for the explicit status, [UNREAL_FULL_PORT_AND_ASSET_PLAN.md](UNREAL_FULL_PORT_AND_ASSET_PLAN.md) for the integrated port and free-asset plan, [ORIGINAL_ASSET_WORKFLOW.md](ORIGINAL_ASSET_WORKFLOW.md) for making original art after pack studies, and [WORLD_FOLIAGE_ASSETS.md](WORLD_FOLIAGE_ASSETS.md) for foliage provenance.

## Verification and collaboration

`Tools/ValidateCohesiveWorld.py` checks the saved map, navigation, placeholder population, boarding lane, Shooter respawn, and replacement ship display in a fresh Unreal commandlet process. The latest saved-map pass is 102/102. Native automation covers a physical board → launch → Mars jump → land → exit → remote market → reboard sequence, MFD navigation, journey save/restore, and deterministic world dressing. These checks do not replace hands-on flight, combat, and long-session tests in the Editor.

After the first clone, collaborators use `git pull` and `git lfs pull` to receive incremental project changes, then rerun `./Tools/InstallAllDependencies.ps1 -VerifyOnly`. If it reports a missing local pack, run the installer without `-VerifyOnly` with Unreal Editor closed. The local asset list lives in `Data/ExternalRuntimeContentManifest.json`, `Data/WorldFoliageDependencies.json`, and `Data/ViktorShipsDependency.json`; each installer validates its inputs. Unreal-generated `Binaries`, `DerivedDataCache`, `Intermediate`, and `Saved` stay local.
